# Architecture

NoteBoard is a single-page React application built with TypeScript and Vite. The entire state of the notes is managed by a centralized `NotesContext` that wraps a `useReducer` store, exposing granular action methods (`addNote`, `updateNote`, `removeNote`, `bringToFront`) rather than a raw dispatch. This keeps consumer components decoupled from the action shape and makes the API surface explicit. On every mutation the context optimistically updates local state and then fires an asynchronous call to a mock REST API layer (`notesApi.ts`), which serializes the notes array to `localStorage`. On mount the provider rehydrates state by calling `fetchNotes()`, so notes survive page reloads.

Drag interactions (move and resize) are powered by a single custom `useDrag` hook that captures the pointer on `pointerdown` and tracks deltas through `pointermove` / `pointerup` — all on the originating element via pointer capture, avoiding the common pitfall of losing the cursor when moving fast. During a drag the hook writes directly to the DOM node's inline styles (via a ref) instead of triggering React re-renders, which keeps 60 fps performance even with many notes. Only when the drag ends does the hook commit the final position or size back into the reducer. The trash-zone deletion works by checking, at pointer-up time, whether the center of the dragged note overlaps the `TrashZone` bounding rectangle exposed through a shared ref.

The project uses Tailwind CSS v4 (integrated as a Vite plugin) for utility-first styling. Notes are rendered as absolutely-positioned elements whose coordinates, dimensions, and z-index come directly from the data model. A small random rotation is applied per note instance for a realistic sticky-note aesthetic. Color selection is handled by an inline `ColorPicker` palette toggled from the note header. Text editing is inline: clicking the note body swaps the static paragraph for a `<textarea>` that auto-focuses; on blur the text is persisted. All code is strictly typed with no `any` usage, and the architecture intentionally avoids third-party component libraries to demonstrate custom solutions for drag-and-drop, state management, and UI composition.
